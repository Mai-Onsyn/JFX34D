# JFX34D 开发文档

## 一、项目是什么

用 LLM Agent 做四维显式多面体片元建模的桌面软件，类似简易 Blender，但面向四维模型。

用户用自然语言与 AI 对话，AI 返回 JSON 操作指令，系统执行四维操作，并实时在 3D 窗口中看到四维模型的投影。

核心表示：顶点是四维 `(x, y, z, w)`，片元是四个顶点构成的四面体。  
目标：让 AI 理解四维并直接建模，替代以往只能靠写复杂代码构建四维模型的方式。

## 二、技术架构

- 桌面应用，双击启动。
- Kotlin + Java + C++ 混写，Maven 构建，一个工程。
- UI 用 JavaFX，3D/4D 视口用 OpenGfx 渲染到 `GL3DRegion`，可叠加 JavaFX UI。
- 3D 用 OpenGL；4D 顶点通过 JNI 交给 C++ 变换，再传回构建四面体给 OpenGL 显示。
- 四维模型全部在 CPU 中，使用 JOML，并扩展了 5×5 矩阵和五维向量。
- Agent 用 Java，独立守护线程，任务串行。LLM 可用本地小模型或 DeepSeek API，直接输出 JSON。
- 中心状态是四维场景对象，不对外暴露。渲染每帧或变化后复制数据给 C++。

## 三、四维基础常识

三维渲染用三角形拼模型，四维渲染用四面体拼模型。四面体是四维的最小片元，由四个四维顶点构成。

三维正方体有 6 个面，四维超立方体有 8 个胞。每个胞本身是一个三维正方体。四维超立方体可以理解为 8 个三维正方体包成的四维体。

三维里“绕轴旋转”本质是在一个二维平面内旋转，轴只是法线。四维里一个轴无法唯一确定一个平面，所以旋转必须说“在哪个平面内旋转”。四维中选两个坐标轴组成一个平面，共有 6 个：XY、XZ、XW、YZ、YW、ZW。其中 XY、YZ、XZ 是三维就有的旋转，XW、YW、ZW 是卷入/卷出第四维的旋转。

四维摄像机有位置 `(x,y,z,w)` 和四个基向量 `vx, vy, vz, vw`。沿 w 轴移动相当于在第四维前后移动。旋转用上述 6 个平面之一。用户只能操作 3D 摄像机观察投影，四维操作权交给 AI。

## 四、渲染流程

1. 四维顶点经过模型变换和四维摄像机变换。
2. 四维到三维投影：把四维模型投影到某个超平面上，得到三维顶点。这是第一次降维。
3. 三维到二维投影：再经过普通 3D 透视或正交投影，得到屏幕坐标。这是第二次降维。
4. OpenGL 根据四面体片元绘制。

用户看到的是四维模型的“三维影子”，就像三维物体的影子是二维的。AI 操作四维模型时，用户看到这个影子实时变化。

## 五、AI 交互流程

用户输入自然语言后，UI 发送事件，Agent 组合 prompt 发给 LLM。LLM 返回 JSON，解析器解析后调用四维接口执行操作，执行结果拼成 Markdown 返回给 LLM，LLM 继续发送操作，直到结束标志。整个过程实时渲染，用户能看到 AI 的操作。

### 5.1 JSON 返回格式

LLM 返回的 JSON 顶层包含：

- `version`：版本号
- `done`：是否结束本轮对话
- `operations`：操作数组

每个操作包含：

- `type`：操作名称，字符串
- `id`：操作 id，整数
- `data`：操作所需数据
- `no_result`：可选，布尔值，默认 true，表示不接收该条执行结果

示例：

```json
{
  "version": 1,
  "done": false,
  "operations": [
    {
      "type": "MOVE_CAMERA_POS",
      "id": 1,
      "no_result": false,
      "data": {
        "axis": "x",
        "distance": -5
      }
    }
  ]
}
```

### 5.2 结束标记

本轮对话结束时，LLM 必须返回：

- `done: true`
- `operations: []`

系统提示词中明确要求：AI 结束本轮对话时，输出空操作集并带上 `done: true`。

解析器先判断 `done`：

- 若 `done: true` 且 `operations` 为空，则结束本轮对话。
- 若 `done: true` 但 `operations` 非空，视为格式错误，返回 Error Markdown，让 LLM 重试。

示例：

```json
{
  "version": 1,
  "done": true,
  "operations": []
}
```

### 5.3 返回给 LLM 的 Markdown

执行结果拼成 Markdown 返回给 LLM。为保证本地小模型稳定，返回值统一使用英文。

成功示例：

```markdown
# MOVE_CAMERA_POS(id=1)
Success
Now Pos=(-5, 0, 0, 0)
```

错误示例：

```markdown
# Error
Reason: Failed to parse JSON, missing data field
```

解析失败时返回 Error Markdown，让 LLM 重试。
## 六、接口与数据格式

四维模型文件后缀 `.4do`，纯文本，类似 obj。标签包括 `v`（顶点四维坐标）、`vn`（四维法向量）、`vc`（顶点颜色）、`t`（四面体，引用索引）。

代码中：
- `Mesh4D(tetrahedrons: List<Tetrahedron>, name: String)`
- `Tetrahedron(v0, v1, v2, v3: Vertex4D)`
- `Vertex4D(pos: Vector4f, color: ColorARGB, normal: Vector4f)`

四维接口包括摄像机位置、摄像机视角、模型操作、模型变换等类别，具体操作名和参数见独立接口文档。接口尚未写完，校赛先实现核心部分。

## 七、开发约定

- 代码放在一个 Maven 工程中，按包划分模块。
- 渲染模块负责四维场景管理、渲染器、输入和四维接口。
- Agent 模块负责 LLM 调用、prompt 组装、JSON 解析、结果拼接。
- UI 模块负责界面布局、事件处理，Handler 可先留空，后续补全。
- Git 一个分支，随时同步。
